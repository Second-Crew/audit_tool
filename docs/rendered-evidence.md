# Rendered-page evidence

The crawler first fetches HTML with DNS validation, redirect checks and robots permission. Pages that contain scripts but yield fewer than 80 characters of cleaned main text become render candidates. A second pass attempts up to 30 of those pages for at most 100 seconds. Browser requests are limited to the audited host and its subdomains, require a public DNS answer, and block service workers and downloads. Rendered HTML has a 900 KB cap. Blog article pages require at least 500 characters of cleaned main text, so a list of related posts cannot be mistaken for the article body. This is an abstention threshold, not a quality grade. The report records whether each page's evidence came from fetched HTML or rendered DOM.

Server configuration is optional: set `RENDER_CHROME_EXECUTABLE_PATH` on a persistent worker/local machine or `RENDER_BROWSER_WS_ENDPOINT` to a trusted Playwright-native browser endpoint. The endpoint must support Playwright `connect`, not a CDP-only endpoint. The full WebSocket URL often contains a secret and must be configured as a server-only secret. A browser service used for public URL auditing should have network isolation from private services. No browser service is provisioned by this change.

For Browserless, enter only a WebSocket URL in the Vercel Secret value, for example `wss://production-sfo.browserless.io/chromium/playwright?token=YOUR_ACTUAL_TOKEN` with the actual token substituted. Do not include `RENDER_BROWSER_WS_ENDPOINT=`, surrounding Markdown, or a placeholder token. Scope the Secret to the intended environment and redeploy after changing it. The client is pinned to Playwright 1.62.1 because [Browserless native connections require a supported version](https://docs.browserless.io/baas/versions); check that list before upgrading. The audit response exposes only safe rendering counts and failure categories in `primary.crawl.summary.rendering`. Redacted connection details appear in Vercel runtime logs; the full endpoint and token must never be logged.

If rendering is unconfigured, times out, or still yields too little content, the audit reports insufficient content evidence. When under 80% of sampled pages have usable text, content-dependent category grades and composite grades are withheld, and absence-based content findings are removed. Fetched HTML title and description observations remain in the agent evidence. A rendered page cannot by itself authorize cold outreach; that source type still requires separate validation. Legacy reports need a new audit to gain this behavior.

A local Chrome check on `secondcrew.com` recovered homepage text where fetched HTML yielded zero. In a 12-page sample, several rendered article pages only showed related-post links; these remain incomplete rather than receiving a content grade. This verifies both recovery and abstention paths, not all website types.
